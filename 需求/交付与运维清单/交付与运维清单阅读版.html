三、运行模式、升级与恢复 🔼 🔽

部署入口先自述并等待确认，通过 fzf 选择本地部署＋内网穿透或服务器部署。当前正常路线在工程内准备缺少的工具、配置账户、编译并前台启动，不自动注册系统服务或打开防火墙。模式取消、空选及选择器错误不应启动业务；完整副作用与按键以各系统说明为准。

环节 当前能力或需落实的方案 成功检查／恢复边界
健康与启动 检查依赖、账户配置、源码与监听地址；单实例启动 /healthz 仅是入口检查，还须真实创建后刷新重读、私有附件授权及重启持久化
本地穿透 可选临时 HTTPS 隧道，整站转发同一后端；随机地址用于短期联调 手机关闭 Wi-Fi，核对真实读写与文件权限；网页演示仍显示不证明服务或隧道在线
停止与重启 前台 Ctrl+C 回收本次进程并保留数据；重复运行复用有效配置 外部新请求确认入口失效；不能把关闭页面当停止服务
常驻、状态与告警 无统一已验收的常驻、状态、重启和告警入口 由运维确定系统机制、权限、启动目录、脱敏日志与恢复步骤并在目标机验证
升级／回滚 尚无统一菜单；需先备份，再在独立发布目录验证候选包，安排切换窗口 应用包回退与数据恢复分别设计；不可逆迁移先明确恢复点、停机与数据损失条件
文件存储备份／恢复 现有说明为正常停服后保存整个 data 与有效配置；恢复前保留原副本 仅复制不是恢复通过；在隔离目录启动，核对案件、金额、附件、交付及操作收据
PG 备份／恢复 academic_runtime_state JSONB 聚合；数据库备份、配置与恢复方案仍需落实 专用隔离数据库演练一致快照和恢复；改 DATABASE_URL 不会自动迁移文件数据
卸载与迁移 程序、配置、数据、隧道路由和第三方账号分别处理 默认保留业务数据；删除应展示准确对象并单独确认；正式迁移核对域名、回调、备份及回退

【不确定 Q-009】当前以源码编译／前台运行为主，未提供通用规范要求的预构建优先及全生命周期入口；隧道超时或退出会清理已启动的后端，与“穿透失败保留健康本地服务”的规范不同。这是现状差异，尚无已确认例外；不得写为符合全部部署要求。是否调整行为及实现范围在主评审收口。

客户端仍按 API 优先和隔离演示合同工作；失败回退不代表后端可用，演示写不补发正式环境。列表空态、重载和本地素材兜底按 AC-11／AC-12 检查。完整工具链及 Web 资源就绪后才能离线预览；鸿蒙在线宿主离线首启不能加载页面。
