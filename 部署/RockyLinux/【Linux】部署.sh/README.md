# RockyLinux 部署入口

**当前依赖流程：** 模式确认后每次核查官方最新稳定Go／fzf，本地模式另查cloudflared；缺失时先按旧锁引导，再用标准库解析器取得最新资产并校验。工具采用项目外、按规范后端路径隔离的版本缓存，外置缓存另有原点与恢复收据。后端及二维码业务库仅限时报告更新、独立回归后更新，源锁不变；退出3提示未完成后按锁构建，退出2停止核对，取消传播。`--check`／`--plan` 保持只读；客户端工程不被自动更新。详细版本、缓存与失败边界见[本平台依赖流程](../README.md#latest-dependencies)。

## 当前商城页面与Demo模式

本地部署＋内网穿透固定使用 `DEMO_MODE=1`、`PAYMENT_MODE=mock`。登录页会展示并允许复制当前配置的管理员、客户实际测试账号密码，支付按模拟成功处理；请为此模式使用专用演示账户与合成数据。服务器部署显式设 `DEMO_MODE=0`，覆盖继承的Demo开关，接口不返回密码；支付沿用显式进程配置，未设置时由后端默认mock。这两个开关不写入 `.runtime/config.env`，终端日志不打印密码；Windows退出时还原调用进程原有环境。

入口按各自 `index.html` 是否存在，分别优先选用 `代码/前端/移动端/Flutter/Dist/ShopClient` 与 `代码/前端/后台管理端/Flutter/Dist/ShopAdmin`。完整工程请保留这些已构建目录；独立后端分发未携带对应构建包时，分别回退到 `代码/后端/后端代码/client-web`、`admin-web` 随包页面。启动日志显示最终目录，不自动构建Flutter、不复制或覆盖静态目录及运行数据。路径从脚本自身位置解析，改名、中文空格和工程外启动不影响选择。

部署与反部署的生命周期核心分别内嵌在本平台两份脚本中，覆盖原点、操作锁、进程身份、数据备份和资源恢复；两份脚本可分别执行，无须加载外部生命周期函数库。确认顺序、状态协议、数据策略及恢复边界见[原点与恢复协议](../../README.md#lifecycle-protocol)。

此目录与实际脚本同名；直接运行本目录内的同名脚本。复制根目录的 `代码/` 与 `部署/` 并保留原相对层级，不能单独移动这个脚本包。

在上一层平台目录可直接双击 [双击部署（快捷入口）.desktop](../双击部署（快捷入口）.desktop)；快捷入口调用本包内的部署实现，复用自述与确认。

**扫码访问：** 地址生成后仍逐行显示完整 URL，并分别生成用户端、管理端的本地二维码。支持颜色且足够宽的终端直接显示黑白码；窄终端、非 TTY、`NO_COLOR` 或 Windows 纯文本环境，打开日志列出的 `.runtime/access-qr.*/index.html`（Windows 为 `access-qr-编号`）扫码，可保存 SVG/PNG。二维码不经过在线服务；隧道地址变化会重新生成，退出时页面标记失效。服务器可通过环境变量或 `.runtime/config.env` 的 `PUBLIC_BASE_URL=https://实际域名` 指定不含账户、查询参数或片段的基地址；未配置时仅显示明确标为“仅本机”的回环入口，手机无法访问。二维码辅助失败只告警，原 URL 与健康服务保留；产物由既有反部署清单管理。详见[二维码输出、固定依赖与使用边界](../../公共组件/地址二维码/README.md)。

## 最低机器配置

正常脚本编译部署预算：64位2核、4 GiB可用内存、20 GiB空闲SSD；图形主机整机至少8 GiB。数据、附件、日志增长另计，未作容量实测。

## 本地部署＋内网穿透

**关闭此运行终端，服务将结束**。本地临时模式在确认公开前及地址生成后的运行日志中单独显示此提示；支持颜色的终端使用红色加粗，非终端、`TERM=dumb` 或 `NO_COLOR` 时显示纯文本，日志不含颜色控制码。当前窗口管理本次后端与隧道，关闭终端或按 `Ctrl+C` 结束本次临时服务，业务数据与账户配置保留。

从本目录开始：

```bash
bash './【Linux】部署.sh' --check
bash './【Linux】部署.sh' --plan
bash './【Linux】部署.sh'
```

阅读自述回车后，fzf选“本地部署＋内网穿透”或“服务器部署”；取消/空选/错误不启动业务。静态锁仅准备引导工具，模式确认后每次检查官方最新稳定Go／fzf，本地模式另查cloudflared；达到版本且健康才复用，新资产核验SHA256及执行健康后放项目外版本缓存，不覆盖全局环境。本地模式先配置不同的非默认密码，默认文件存储、127.0.0.1:8080，确认公网后由脚本先验本次后端健康，再建免费Cloudflare Quick随机HTTPS；无需账号或域名。服务器模式只运行后端，不建隧道。

Ctrl+C回收本次后端和隧道，数据保留；不会按进程名/端口停止其它服务。Quick无SLA，大陆网络需实测，地址会变，200在途且不支持SSE。45秒无地址会停止并提示排查。FreeBSD/ARM64和Alpine的原生工具/ABI限制按平台说明核对，不下载错架构。

双项目端口为学术8080、维修8098，各用独立HTTPS整站同源入口；保留公网Host，不重写localhost。必须用手机移动网络验health、真实登录/写入刷新重读/私有文件权限，演示页面不代表服务连通。详细cpolar备选、固定地址、日志、停止与备份见[本平台说明](../README.md#local-tunnel)。

## 反部署与恢复

- [双击反部署（快捷入口）.desktop](../双击反部署（快捷入口）.desktop)调用独立的 [【Linux】反部署.sh](../【Linux】反部署.sh/【Linux】反部署.sh)，不复用部署快捷入口。无图形桌面时使用 `bash '../【Linux】反部署.sh/【Linux】反部署.sh'`。
- 数据通过fzf选择备份（默认）或清零，再经过默认取消的危险菜单和空格复核；备份包含文件数据与账户配置，保存到后端代码目录同级 `反部署备份/`，校验和快照复核通过才清源。取消、备份失败或源发生变化均保留数据。
- 部署前保存 `.runtime` / `.tools` 原点，部署后按文件摘要记录实际变更。反部署仅回收身份匹配的本次进程，并恢复清单内仍未被后续修改的资源。共享、未知、旧部署缺少记录、系统包安装分支及非空数据库连接串都会保留并报告未完成，不能称为已完全恢复。
- [脚本详细说明](../【Linux】反部署.sh/README.md)与[原点与恢复协议](../../README.md#lifecycle-protocol)说明操作锁、重试和私密恢复包；反部署完成保留原点审计，下一次全新部署前先私密归档 `.deployment-state`。隔离检查与本系统原生、实库恢复分别验收。

反部署确认后的纯文本审计位于后端 `.deployment-state/posix/operations.log`；资源差异见 `current.tsv` / `restored.tsv`，数据恢复位置见 `data-pending` / `data-destination`。未完成项会返回非零并保留现场。

**终端配色保护：** 独立运行时，在支持完整保存与恢复配色的交互终端中临时使用黑底白字及统一强调色；正常结束、失败或可捕获中断后恢复进入前的配色，不修改终端全局偏好或 Shell 启动配置。不支持完整保护、无交互终端、`NO_COLOR`、既有纯文本模式和 Sourcetree 场景不切换配色，并沿用纯文本输出约定。强制终止（如 `kill -9`）无法由脚本自身保证恢复，请使用运行时显示的独立恢复入口。
