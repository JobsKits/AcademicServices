# FreeBSD 反部署入口

部署与反部署的生命周期核心分别内嵌在本平台两份脚本中，覆盖原点、操作锁、进程身份、数据备份和资源恢复；两份脚本可分别执行，无须加载外部生命周期函数库。确认顺序、状态协议、数据策略及恢复边界见[原点与恢复协议](../../README.md#lifecycle-protocol)。

直接运行本目录内的 [【FreeBSD】反部署.sh](./【FreeBSD】反部署.sh)，或在上一层打开 [双击反部署（快捷入口）.desktop](../双击反部署（快捷入口）.desktop)。完整复制根目录的 `代码/`、`部署/`，保持层级；快捷入口只转交本包唯一实现，图形启动依赖本系统桌面与终端。

```shell
sh './【FreeBSD】反部署.sh' --check
sh './【FreeBSD】反部署.sh' --plan
sh './【FreeBSD】反部署.sh'
```

- 自述后按回车，在 fzf 用方向键/Tab选择“数据库数据备份”（默认）或“数据库数据清零”；危险菜单默认取消，选择确认后还须按一次空格再回车。Esc、Ctrl+C、空选、EOF或选择器异常均取消。复用已有健康fzf，可用 `FZF_BIN` 指定；反部署不下载安装选择器。
- 经确认后只停止部署清单记录且身份仍匹配的本次包装、后端和隧道，不按名称或端口杀进程。数据默认保存至后端代码目录外同级的 `反部署备份/`，包含完整文件数据与匹配配置；验证完整和源快照未变后清源。清零不保存数据副本，不能撤销。
- 按部署前后清单恢复旧程序/配置、删除仍与清单一致的新工具与缓存。原有、共享、未知、后续修改及无记录旧部署全部保留，存在差异返回失败；系统包安装分支保留并报告未完全恢复，不整片删除环境。
- 非空 `DATABASE_URL` 是外部数据库模式，当前安全阻断自动反部署并保留数据库和资源，需取得对应数据库备份/恢复证据后另行处理，不能把本地文件包当作数据库备份。
- 原点与操作审计在后端 `.deployment-state/`；中断重试使用既有快照和恢复包，不重新备份变化源再清零。完成后仍保留审计和owner；全新部署前先把该状态目录归档到项目外私密位置。
- `--check` / `--plan` 仅校验入口、系统和完整归属记录，不停止或删除。缺记录失败不表示旧数据被删除。语法/隔离用例与 FreeBSD 原生桌面、真实部署和数据库恢复分别验收。

完整原点协议、备份阶段及限制见[原点与恢复协议](../../README.md#lifecycle-protocol)，日志和运行条件见[本系统说明](../README.md)。恢复包及原点含私密配置，勿提交或公开。

反部署确认后的纯文本审计位于后端 `.deployment-state/posix/operations.log`；资源差异见 `current.tsv` / `restored.tsv`，数据恢复位置见 `data-pending` / `data-destination`。未完成项会返回非零并保留现场。
