# Windows 反部署

部署与反部署的生命周期核心分别内嵌在本平台两份脚本中，覆盖原点、操作锁、进程身份、数据备份和资源恢复；两份脚本可分别执行，无须加载外部生命周期函数库。确认顺序、状态协议、数据策略及恢复边界见[原点与恢复协议](../../README.md#lifecycle-protocol)。

双击上级 [【Windows】双击反部署（快捷入口）.cmd](../【Windows】双击反部署（快捷入口）.cmd)，或从当前目录运行：

```powershell
powershell.exe -NoProfile -File '.\【Windows】反部署.ps1' -Check
powershell.exe -NoProfile -File '.\【Windows】反部署.ps1' -Plan
powershell.exe -NoProfile -File '.\【Windows】反部署.ps1'
```

- 先关闭部署窗口，完整保留仓库内 `代码/` 与 `部署/` 的相对层级。`-Check`/`-Plan` 只读审阅原点，不联网、不创建日志、不停止进程、不改业务数据。没有 Windows 原点的旧部署会停止，不能借重新部署制造虚假原点。
- 阅读内置自述后回车，fzf 默认选“数据库数据备份”。方向键或 Tab 选择；Esc 取消。另有“数据库数据清零”，不制作数据副本且不可恢复。策略选择后显示准确范围，再进入默认取消的危险确认；明确选执行后须按空格复核，其它键取消。取消和选择器失败都不执行反部署。
- 复用 `FZF_BIN`、当前环境或部署缓存中的健康 fzf，不为卸载联网安装。工具缺失时先提供已核验的原生可执行文件。选择器临时清空外部 fzf 选项和命令，随后恢复宿主编码和环境。
- 本项目数据为后端目录的 `data/`，文件模式的附件包含在数据中。默认备份同时覆盖账户配置，校验成功且源内容仍匹配确认快照后，清理本次新建的源数据；备份落在后端实现目录之外的 `UndeploymentBackups/`。原有 `data` 继续保留并报告部分恢复，不能用“反部署完成”冒充已回到原点。
- `.runtime` 和 `.tools` 按逐项原点恢复：原有文件/权限恢复，本次新增且内容未变的产物删除，原有未改工具保留。未知或后续修改的对象、活数据锁、身份不符进程、损坏备份、变更快照都会停止并保留现场。强制停止留下的本次服务标记，只有部署封存了同一进程/时间/内容证据且 PID 明确已死时，才在复核摘要后移入原点审计；未知标记不删除。原点与操作记录保留在 `.deployment-state/windows/`，失败后用相同数据策略重试，不能删除清单掩盖差异。完整完成后 owner 与审计仍保留；若要重新部署，先将整个 `.deployment-state` 私密归档到项目外，不原地删掉恢复依据。
- 使用外部 PostgreSQL 时，当前没有数据库原生备份与清零支持，全部保留并明确报错。该入口不删除远端数据库、不卸载全局 SDK、不改防火墙、自启、系统服务或全局 PATH。
- 原点保存敏感原配置，备份也含账户资料；不要上传、公开或复制给无权限人员。恢复业务时先复制备份到独立位置，核对匹配配置与服务已停止，再按[部署说明](../README.md)部署，不能让两实例同时写同一数据目录。

当前已通过 PowerShell 语法与临时目录的文件逻辑隔离验证；Windows 原生双击、ACL/进程、真实服务与真实数据库均未验收。


## 原点记录与分阶段恢复

- 部署写入前保存 `.runtime`、`.tools` 的逐项内容摘要、原文件和 Windows ACL，记录部署前 `data` 是否已存在；部署结束后封存实际产物。外部复用的 Go、fzf、cloudflared 没有被复制进项目，不纳入删除范围。
- 原点位于后端代码目录的 `.deployment-state/windows/`，`receipt.json` 是重试依据；`original/` 包含原配置，Windows 下按当前账户保护。该目录含敏感配置，不能上传、公开或手工清空。
- 全系统共用 `.deployment-state/owner` 和 `operation-lock/`。Windows 另外用独占文件句柄串行化本侧抢锁；异系统原点、活锁和身份不明的锁停止操作；仅明确死 PID 的已知格式锁可恢复。运行部署窗口持有锁，反部署前先关闭该窗口。Windows 强制停止后端可能留下 `.server-lock`；部署退出时仅封存本次 server 进程身份、时间与标记摘要匹配且 PID 已死的证据，反部署再核对后把该标记隔离到原点审计中。未知或变化的标记保留并停止。
- 再次部署沿用同一原点；产物后来发生变化时停止，保留用户新内容。反部署完成后仍保留 owner 与收据供重复检查。再次部署前须将整个 `.deployment-state` 私密归档到项目外，再由新部署建立原点；不自动覆盖或复用旧记录。
- 文件存储备份完整 `data`（包括状态、附件）与匹配的 `config.env`，输出到后端实现目录之外的 `UndeploymentBackups/Windows-原点编号/`。备份副本校验后再次核对源快照；源变化或备份损坏时停止，不偷偷刷新备份后清零。
- 新建数据目录先移到同父唯一隔离名、再核对内容后清理；原有数据不自动清零，保留并以非零结果报告部分恢复。先前就存在且内容未变的共享 SDK/缓存保留。后续新增、改动、未知及符号链接对象均保守保留。
- 外部 PostgreSQL 没有原生备份与清零实现，入口明确阻断整个反部署，不能把文件副本当作数据库备份。无原点的旧部署也不能推断归属后删除。
