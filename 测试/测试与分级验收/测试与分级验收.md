## 一、<span id="levels">三级准入与结论规则</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

| 等级 | 必须具备的可检查结果 | 当前不能据此放行的事项 |
| --- | --- | --- |
| 一级：基础可运行 | 本期确认范围完整，约定目标环境安装、启动、登录、核心读写及重启全部通过；主流程和关键异常闭环 | 未冻结本期范围；部分端无安装及真实业务证据；演示数据不得代替服务器写入 |
| 二级：可商用 | 包含一级；已评审用例全部执行，关键业务通过；达到约定性能，具备正式身份、必要权限、依赖资质、日志、备份恢复、升级回滚与发布条件 | 固定身份、业务条款未收口、真实渠道及运维缺口尚在，见 GAP 清单 |
| 三级：工业化 | 包含二级；按确认目标验证易用、健壮、封装、可移植、容量、持续运行、发布和故障恢复 | 尚无生产容量、长期运行、故障及灾备的完整证据；不为等级默认增加复杂集群 |

崩溃、流程阻断、越权、关键计算错误、数据损坏或交易错误属于对应范围的阻断条件。遮挡关键动作、不可读或无法完成操作也不能按轻微视觉问题放行。其它缺陷等级、允许数量和时限在执行前填写，不由本册虚构数值。

验收结论由约定验收人给出“通过／有条件通过／不通过”。有条件通过须列明非阻断遗留、责任人和期限；缺失输入或未执行用例不得计入通过。状态仅使用“通过、失败、未执行、阻塞、不适用”，阻塞与不适用均写依据。

## 四、<span id="execution">目录、复跑与执行边界</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

测试源码与执行证据集中在本目录，核心代码位于平级 `代码/`。语言要求的测试执行上下文仍由入口显式设置，不把业务源码复制进测试目录，也不在核心代码内保留另一套测试副本。

| 目录 | 作用与依赖 |
| --- | --- |
| `后端/` | [**Go**](https://go.dev/) 同包测试；运行器生成临时 overlay，将测试映射至后端包上下文，测试物理文件留在外部 |
| `后端/接口/` | 独立真实 HTTP 联调；使用临时数据和回环端口 |
| `部署/` | 部署基础与双模式沙盒，不与业务前后端测试混放 |
| `前端/微信小程序/` | 微信客户端仓库逻辑测试 |
| `前端/PC端/Python/` | 仓库、Qt 界面、引导与打包保护；源码路径由入口加入，不安装全局模块 |
| `前端/移动端/Flutter/` | [**Flutter**](https://flutter.dev/) 用例及 [**iOS**](https://developer.apple.com/ios/) 测试源码；通过原项目 SDK 和依赖解析，设备验收另行执行 |
| `前端/移动端/鸿蒙/` | 宿主生成与配置合同；不证明 HAP、签名或 ArkWeb 真机通过 |
| `前端/后台管理端/Flutter/` | 后台资金动作、交付选择及宽窄窗口报价测试；复用移动 Flutter 的依赖上下文 |
| `报告与证据/` | 原验证日志、截图与交叉编译记录；保留原版本与日期 |

在仓库根读取统一入口用法：

```shell
python3 './测试/运行测试.py/运行测试.py' --help
```

按入口列出的测试组选择执行，工具路径从当前环境或显式参数传入。Go 测试未提供专用 `TEST_DATABASE_URL` 时，PG 场景会明确跳过；必须保留跳过数量，不能报告为原生数据库通过。移动端沿用已锁 SDK／插件，目录迁移不构成升级授权；依赖缺失时记录阻塞，不将下载安装或清理环境作为默认测试动作。

部署沙盒使用假 Go／fzf／隧道与临时文件，不能证明真实公网或提供商连通。真实 HTTP 会构建并启动独立后端进程；Qt 测试需要对应桌面运行库。各组应在具备依赖的环境执行，失败保留日志及退出码。
