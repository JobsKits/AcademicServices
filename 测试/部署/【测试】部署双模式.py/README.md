# 部署双模式沙盒回归

从本目录运行 `python3 './【测试】部署双模式.py'`。仅测试环境需要Python；交付部署脚本不依赖Python。

临时副本沿用真实入口内嵌的生命周期函数，不补建外部生命周期函数库。部署原点、退出封存与反部署恢复的配对验证见[反部署隔离测试](../【测试】反部署.py/README.md)。

直接调用 `../../../部署/MacOS/【MacOS】部署.command/【MacOS】部署.command` 的临时副本，使用中文/空格及改名目录、假Go/fzf/cloudflared、真实PTY和临时回环HTTP服务；不启动项目后端，不连接隧道提供商，不发布公网，不安装系统工具。覆盖模式严格选择、只读计划、端口占用、健康顺序、URL超时、启动失败的终端诊断与凭据脱敏，以及中断／SIGHUP时精准回收本次子进程。

会话专项覆盖连续启动先停止旧后端与隧道再恢复健康、原配置及业务数据保留、模式取消与只读检查保留旧服务、真正关闭控制PTY、强制结束入口后的守护回收及再次启动、没有关窗信号时的终端父进程消失兜底、优雅退出途中主入口被强制结束的守护接续、原生接管锁竞争时保留旧服务，以及无关PID／伪造旧身份不被停止。关闭PTY是隔离终端行为验证，不代替用户终端App的真实关窗验收。

二维码辅助以假编译器和独立假工具验证用户端／管理端完整URL、独占本轮页面、结束失效、生命周期清单纳入、地址变化后替换旧页面，以及构建／生成失败时健康服务继续运行；二维码编码与真实解码需另行运行独立工具验证。MacOS/zsh为实际运行覆盖，其它平台语法/模拟结果不能代替实机验收。
