🔥 前言

采用微信小程序官方原生 JavaScript／WXML／WXSS／JSON，零第三方运行依赖，与其它客户端共用商城 API。首页、我的订单、个人中心是三项图文 Tab，不附加序号；个人中心显示登录用户名与头像，提供待付款／待完成／待评价／已完成四个订单入口。账户切换、退出及主题位于设置。课程与服务均为虚拟商品。

一、打开与连接 🔼 🔽

  • 微信开发者工具导入本目录。配置使用 touristappid 供开发预览；正式项目填写自己的 AppID 并配置 HTTPS 合法域名。当前没有执行开发者工具编译，基础库的实际解析版本需在工具中核验。
  • 设置页维护完整 API 地址（含 /api/v1）和请求超时（500—10000 毫秒，默认2500）。开发者工具可用 http://127.0.0.1:8080/api/v1，手机必须使用手机可达的 HTTPS 地址；更改连接会退出当前会话。
  • 登录页读取 /shop-config：只有部署显式启用 Demo 模式才显示后端提供的实际角色、账号、密码，每个字段均可单独复制并提示成功；没有演示账户快捷按钮。复制后粘贴到登录表单，正常请求真实登录。仅已获取的显式 Demo 配置与匹配凭据允许网络异常时进入隔离演示；正式模式、错误密码或权限拒绝不会变成成功。密码、token 及 Demo 凭据不写本地永久存储。

二、购买、付款及订单 🔼 🔽

  • 首页原生轮播先显示随包三张海报，后台 /banners 配置成功后覆盖。成功返回空数组表示运营已关闭轮播，隐藏整块轮播及控制；首次请求失败保留随包海报，后续失败保留上次成功配置，包括已关闭状态，迟到响应不能重新打开已关闭轮播。后台网络图先显示本地品牌，成功后覆盖；base64 图片先写入小程序私有文件再显示，有限缓存只清理本功能自己创建的图片。主分类毕业论文／普刊／编译与横向 swiper 双向联动，各自展示商品、空态和重载。
  • 轮播只有一张时静态展示，不开自动播放、循环手势或分页点；多张使用原生swiper循环。设置可关闭自动播放、选择3／5／8／10／15秒间隔，或开启减少动效改为手动。拖动期间暂停，松手后由原生swiper从完整间隔恢复；分页标识为当前实心、其余空心，可点击切换，不显示播放按钮或数字页码。页面隐藏、切Tab、应用后台、轮播离屏及销毁时停止，回到可见前台后按设置恢复。只使用原生swiper计时，不叠加JavaScript定时器。
  • 轮播可配置跳转链接。小程序无法任意唤起系统默认浏览器：点击先说明平台限制，可选择域名受限的 HTTPS web-view，或复制链接在浏览器打开；HTTP 链接及网页加载失败提供复制回退。正式使用须配置业务域名，不能把本实现称为任意外部浏览器已经唤起。
  • 商品详情展示名称、价格、简介、详情分节和库存；已下架或缺货无法新购。下单传商品版本，金额以服务端快照为准，历史订单不随后台改价变化。
  • 未登录购买先进入登录，成功返回原详情并保留填写内容，仍须主动点击购买；登录不会自动创建订单或付款。登录失败保留账号和密码供修正，提示持续显示。普通Tab切换保留订单筛选，个人中心四个状态入口才指定新筛选；页面返回沿用原生缓存，不主动滚回顶部。
  • 购买可填写订单需求、联系方式及交付要求。未被商户接单且服务仍未开始时，待付款或待完成订单允许编辑这三个字段；商户开始服务视为接单，接单时间、服务中、已交付及终态均锁定。界面校验 editable、accepted_at、履约和交易状态，后端再次校验版本及权限，不能编辑商品、金额与数量。
  • 下单后进入待付款订单，弹出支付宝／微信渠道收银台；关闭不付款，主动点击确认才模拟成功。收银台明确提示不会扣款，订单保留渠道、金额与 MOCK 标记。无商户 Key 时不生成官方支付单，不声称已唤起有效官方付款流程。
  • 订单支持全部、待付款、待完成、待评价、已完成筛选。未付订单可取消；站方通过管理端开始服务和提交交付，买方在已交付后确认完成，再评分／填写评价。商户账号看到对应卖方状态及管理端操作提示，不展示买方付款、编辑、确认或评价操作。不存在物流及签收流程，小程序不提供站方履约权限。
  • 商品、订单和详情失败态均提供完整无数据组件和重载。商品图先展示打包品牌图，再覆盖后台商品图；异步图失败保留品牌图，重载后允许再次加载。品牌资源复用仓库自有 icon.png，未下载或冒用参考站宣传素材。

三、服务优先与写入恢复 🔼 🔽

  • 每次进入、重载与写操作均请求 API；尚无成功内容时，网络、超时或响应无法解析可使用隔离演示数据。已有真实商品或订单时保留原内容并持续标记未刷新，不把演示内容当成这次请求成功。后续成功响应自动覆盖，真实空列表保持空态。
  • 本地演示的订单仅保存在当前会话，不自动上传；退出清除私有缓存。服务恢复后如演示身份尚无真实 token，需正常登录才能读取真实私有订单。
  • 真实写请求结果未知时，不报告本地付款成功：保存原提交键与正文，阻止再次下单，订单页可按原键核对收据或重试；404 未查到收据不解除阻塞。待核对记录按 API 与用户隔离保存，不含密码／token。
  • 401 清会话和私有显示，提供重新登录入口；403 显示无权限，404 显示资源不可用，受限订单详情及列表随即清除；409 需重载版本后确认，422 保留表单供修正。需求编辑遇到会话过期时保留本页草稿，同一账号登录返回后可继续确认提交，切换账号则清除草稿。失败或未知写入均不清空购买输入。仓库写锁防止并发双下单，旧请求不能覆盖新会话或更新版本。

四、语言与主题 🔼 🔽

设置页支持简体中文、繁体中文、藏文、英文、日文、法文、西班牙文、德文、俄罗斯文、韩文，支付与订单文案同步切换；后台输入的动态商品与交付内容保持原输入语言。白天、黑夜、跟随系统三主题可用，系统模式监听主题变化；偏好保存在设备本地。主界面使用米白、暖棕和低饱和卡片，深色保留暖深底与易读对比。

五、验证及限制 🔼 🔽

在仓库根运行：

node --test ./测试/前端/微信小程序/test_shop.cjs ./测试/前端/微信小程序/test_mini.cjs

当前仓库逻辑测试78项通过（商城58项、HTTP及幂等20项），包括单图静态、多图循环、前后台／切Tab／离屏暂停、手势松开恢复、分页点选、迟到恢复取消及减少动效，以及登录返回、失败表单保留、账号隔离、权限恢复、筛选保留、卖方视图和运营主动关闭。未执行微信开发者工具编译、iOS／Android微信真机、微信身份／手机号授权、外部真实支付、订阅消息、体验版、提审和发布，不能用 Node 测试代替设备验收。真机需验证布局、暗色、十语言字体与键盘、原生滚动／返回位置、swiper生命周期、网络恢复和模拟购买闭环。
