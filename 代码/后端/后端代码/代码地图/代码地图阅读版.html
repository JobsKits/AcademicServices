🔥 前言

本图只定位 Go 服务实现。接口契约在本实现的外层同级维护；测试源码统一外置，通过运行器临时 overlay 进入 Go 包上下文，不复制回核心代码。路径均从当前文档相对指向源码；跨单元内容只通过链接引用。

一、入口与模块职责 🔼 🔽

本单元路径 职责
cmd/server/main.go 配置、存储启动、HTTP 服务、优雅退出。
internal/platform/http.go 登录／会话／限流／CORS、接口与静态 SPA／私有附件。
internal/platform/shop.go 商城商品、交易订单、双渠道mock支付、履约、评价及原子幂等动作。
internal/platform/shop_http.go 商品／后台商品／商城订单／写结果对账HTTP资源。
internal/platform/engine.go 需求、报价、订单、退款、交付、修改、取消及售后原子动作。
internal/platform/model.go 领域类型、快照、公开视图、状态汇总。
internal/platform/store.go 文件原子替换与实例锁、可选 PostgreSQL 聚合事务。
Migrations/001_runtime.sql 运行聚合存储的 DDL；不等于需求设计中的完整关系表已上线。
go.mod Go 工具链与模块依赖声明。

二、本单元关系 🔼 🔽

flowchart LR
    Main[cmd/server/main.go] --> Http[platform/http.go]
    Http --> Engine[platform/engine.go]
    Engine --> Model[platform/model.go]
    Engine --> Store[platform/store.go]

三、共享源与外部依赖 🔼 🔽

  • 唯一接口契约：所有客户端共用，集中维护
  • 分系统部署导航：分发时保持根目录的代码与部署并列，后端留在代码/后端/后端代码；各系统脚本在自身单元维护
  • 后台 Web 构建地图：Go 托管 /admin/ 构建产物；不接管后台源码
  • 用户 Web 构建地图：Go 托管 /client/ 构建产物；不接管 Flutter 源码

四、外置测试与验证边界 🔼 🔽

  • engine_test.go：原混合地图的状态、资金、并发及存储测试定位；物理源码已在外层

  • http_test.go：HTTP 保护测试

  • shop_test.go：商品快照／版本／缺货、双渠道付款、双方权限、并发、重启及商城HTTP资源

  • test_http.py：通过真实服务子进程跑整单闭环

  • 本单元使用说明：运行、构建及当前限制

  • 统一测试说明：各职责的执行入口与证据位置
