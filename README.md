## 🔥 <span id="前言">前言</span>

面向客户与运营人员，管理毕业论文、普刊、编译三项服务的需求、人工报价、订单、交付和售后。维护者 Jobs，项目别名“陈泉羽项目”，当前为在研 MVP／可运行联调版；“知序”是实现暂名。真实客户身份、细分员工权限、正式支付与全平台验收尚未完成。

桌面采用 [**Python**](https://www.python.org)／[**PySide6**](https://doc.qt.io/qtforpython/)，移动与管理端采用 [**Flutter**](https://flutter.dev/)，后端采用 [**Go**](https://go.dev/)。这些技术方向已经用户确认，软件项目从零到一 Skill 的原生默认规则不替换它们。微信原生小程序已确认纳入本期独立前端交付，入口为[微信小程序工程](./代码/前端/微信小程序/README.md)；开发者工具、真机业务、体验版、提审和发布仍须分别验证。鸿蒙在线宿主认可与其它端分期签收边界仍见主评审 Q-007。

人工核验资金台账只记录收退款证据，不实际划款。各客户端失败回退到隔离演示；演示结果不能作为服务端持久化或付款成功证据。

## 二、<span id="layout">目录与管理边界</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

```text
学术服务平台/
├── README.md
├── 代码/
│   ├── 前端/
│   │   ├── PC端/Python/         # Windows、MacOS 桌面程序
│   │   ├── 移动端/
│   │   │   ├── Flutter/        # 跨平台用户端与共享业务包
│   │   │   └── 鸿蒙/           # 现有 ArkTS 在线宿主
│   │   ├── 后台管理端/Flutter/ # 独立后台入口，依赖共享业务包
│   │   └── 微信小程序/         # 微信官方原生前端
│   └── 后端/
│       ├── 接口契约/           # 唯一接口说明
│       └── 后端代码/           # Go 服务与运行迁移
├── 部署/                        # 各操作系统平台独立部署入口
├── 测试/                        # 按前端、后端、部署归类的测试、执行入口与证据
└── 需求/                        # 唯一需求资料、设计、评审和交付说明
```

代码、测试、需求三个资料主目录的一级仅保留 `README.md` 与子目录；文档原稿、同主题阅读版及附件按职责或标题集中，入口由本页导航。

自定义英文目录以大写字母开头，平台目录和自维护文案统一使用 `MacOS`；发布包放各工程 `Dist/`。保留用户指定专名 `iOS`，以及实际工具链固定目录和语言包身份（如 Flutter 的 `lib/ios/android/web`、Go 的 `cmd/server` 与 `internal/platform`、Python 的 `src/zhixu`）；不把这些内部例外用于任意自定义目录。具体迁移与验证见[目录命名核验](./测试/目录命名验证/目录命名验证.md)。

本仓为单一 Git 工作树，未登记 `.gitmodules`，四个职责目录统一由根仓管理。原外层需求资料合并至 `需求/`，核心代码内不保留重复需求、测试源码或测试报告。各端内部 `lib`、`src`、`ios`、`android`、`internal` 等工具链标准目录保留。不保留项目自维护的 `artifacts/`；存量产物已迁到对应工程的 `Dist/`。构建与安装包按现有忽略规则留在本地；不将发布包、SDK、依赖和生成代码混入自维护源码。没有 CodeGraph 索引，从[各独立工程的地图导航](./代码/工程总览/README.md)进入定位。

## 三、<span id="run">运行与验证</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

先阅读[分平台部署说明](./部署/README.md)。分发时同时复制根目录的 `代码/` 与 `部署/` 并保留原相对层级，再运行部署目录的对应系统入口，通过菜单选择本地部署＋内网穿透或服务器部署。正常脚本会联网准备缺少的工具、编译并启动服务；初次配置不同的客户与管理员密码，取消不启动业务。**关闭此运行终端，服务将结束**。停止按 Ctrl+C，保留业务数据。最低资源目前是工程预算，未做下限硬件验收。

开发者在仓库根目录进入后端运行：

```shell
cd './代码/后端/后端代码'
go run ./cmd/server
```

独立测试环境、各端测试命令与未执行项见[测试计划](./测试/测试与分级验收/测试与分级验收.md#execution)和[统一测试入口](./测试/README.md)。构建、安装、目标环境业务验收和正式渠道发布分别登记；旧报告不能替代当前源码复测。
